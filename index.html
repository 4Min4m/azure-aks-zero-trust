A zero-trust AKS platform, and a database that catches its own tampering.

A private Azure Kubernetes cluster with no public API server, no static credentials anywhere, and a payments-style audit table on Azure SQL Ledger that cryptographically proves whether its own history has been altered. Built as a hands-on demonstration of zero-trust platform design — from cluster access to pod identity to policy enforcement to the audit trail itself.

the centerpiece

Watch it catch tampering

The ledger table rejects direct edits to its own history outright. For the harder case — data altered below the database engine — a digest verification later proves exactly which block stopped matching. Both are reproducible from the scripts in the repo.

What "zero-trust" means concretely, here

✓

No public API serverPrivate cluster — not IP-restricted, genuinely absent from the internet

✓

No static cluster credentialsLocal accounts disabled; access is Entra ID or ARM-mediated only

✓

No public data-plane endpointsSQL, Storage, and Key Vault reachable only via Private Endpoint

✓

No long-lived pod secretsWorkload Identity issues short-lived, auto-rotated tokens

✓

No un-pinned container imagesPolicy-enforced allowed registries, resource limits, no :latest

✓

Tamper-evident, not just tamper-loggedSQL Ledger detects — with proof — not just records
